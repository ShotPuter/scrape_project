# Прямой RES: поиск компаний и очередь CVE

Первый этап реализован в `src/sites/res`, запуск — `scripts/res_search.sh`.
Аккаунт Google/DeQuienes и платная подписка не требуются. Вход: таблица companies
существующей `companies.sqlite3`. Для каждой компании поиск выполняется по
проверенному RUT, иначе по полному названию. Выбирается Registro Sociedades.

## Запуск

```bash
# Пилот до 50 компаний: один браузер, одна вкладка, общий темп 6 поисков/минуту.
bash scripts/res_search.sh --limit 50

# Две вкладки и именованный запуск с общим лимитом 50 разных компаний.
bash scripts/res_search.sh --limit 50 --workers 2 --run-id res-pilot-50 \
  --rate-per-minute 12

# Продолжить тот же запуск, сохраняя исходный предел 50.
bash scripts/res_search.sh --limit 50 --workers 2 --run-id res-pilot-50

# Статистика и экспорт без браузера/сети.
bash scripts/res_search.sh --action status
bash scripts/res_search.sh --action export
```

По умолчанию используются `data/dequienes-companies-2025/companies.sqlite3`
и отдельный профиль `data/res-search-profile`. Пути задаются `--output` и
`--profile`. Уже завершённые и явно отрицательные результаты не повторяются.
Без `--run-id` каждый запуск получает отдельный лимит; с тем же ID лимит
остаётся общим для всех повторов. `--limit 0` не открывает браузер. Несколько
процессов могут разделять базу с разными профилями, но для первого пилота
рекомендуется один процесс. `--company-id` ограничивает поиск заданными ID из БД.

## Несколько браузеров, вкладки и промежуточные результаты

Оба скрипта поддерживают `--browsers` и `--tabs-per-browser`.
Пять браузеров с двумя вкладками дают 10 обработчиков одной очереди:

```bash
# До 100 компаний: общий лимит, пять браузеров по две вкладки.
bash scripts/res_search.sh --limit 100 --run-id res-companies-100 \
  --browsers 5 --tabs-per-browser 2 --rate-per-minute 6 \
  --profile data/res-search-pilot/profile \
  --checkpoint-interval 15 --headed --captcha-wait 120

# После поиска — до 100 PDF из накопленной очереди.
bash scripts/res_download.sh --limit 100 --run-id res-pdf-100 \
  --browsers 5 --tabs-per-browser 2 --rate-per-minute 6 \
  --checkpoint-interval 15 --headed --captcha-wait 120
```

`--limit 100` относится ко всему запуску; это не 100 заданий на каждый браузер.
Темп `--rate-per-minute 6` тоже общий для всех обработчиков стадии.
Число обработчиков равно browsers × tabs-per-browser. Прежний `--workers 2`
сохранён как псевдоним числа вкладок на браузер; одновременно с
`--tabs-per-browser` его задавать нельзя. Лимит поиска считается в компаниях,
лимит скачивания — в CVE/PDF. Найденные PDF могут не соответствовать числу
компаний: у компании бывает несколько документов или ни одного.

Каждый экземпляр получает собственный постоянный профиль. Первый использует
заданный `--profile`, остальные — соседние каталоги с суффиксами
`-browser-2` … `-browser-5`. На следующем запуске используются те же каталоги,
без пересоздания или смены профиля после CAPTCHA. Для RES не требуется
перенос аккаунта Google. Занятый профиль не перезаписывается.
Браузеры запускаются последовательно из-за сбоя установленной версии Camoufox
при конкурентной инициализации; после запуска обработчики работают параллельно.
Пул открывается по необходимости: завершённая очередь и восстановление PDF
из локального manifest не требуют запуска всех пяти браузеров.

После каждого задания результат коммитится в SQLite и атомарно обновляются
JSON/CSV. Дополнительно каждые `--checkpoint-interval` секунд (по умолчанию 15)
сохраняется промежуточный отчёт, даже если запросы ещё выполняются. JSON включает
`state`, `updated_at`, число выбранных заданий и статусы в `progress`, параметры
пула и пути профилей. Каждый результат содержит `worker` с номером браузера и
вкладки. Отчёты поиска: `res_search_report.json/csv` и
`res_searches/<run_id>.json/csv`; скачивания: `res_download_report.json/csv` и
`res_downloads/<run_id>.json/csv`. БД остаётся основным источником для продолжения.

После Ctrl+C достаточно повторить ту же команду с прежними `--run-id`,
`--limit`, `--output` и `--profile`. Можно поменять число браузеров и вкладок:
общий бюджет и завершённые задания сохранятся. Для ошибок CAPTCHA/блокировки
добавьте `--retry-errors`. При CAPTCHA новые задания останавливаются во всём
пуле; уже выполнявшиеся запросы могут закончиться и сохранить результаты.
Ожидание очередного слота темпа запросов прерывается сразу при остановке.
После жёсткого завершения процесса незавершённые задания становятся доступны
после истечения аренды (180 секунд после последнего heartbeat).

Проверки пула: реальный запуск пяти Camoufox по две вкладки на локальных
страницах (`data/res-multibrowser-smoke/report.json`, без запросов к RES);
автоматические тесты общего лимита 100 из 120 заданий для обеих стадий,
сохранения при прерывании и продолжения без повторной обработки.

## Данные и очередь

`res_company_lookup` независима от DeQuienes `company_lookup`. Прежний
`no_cve_found` из DeQuienes не исключает компанию из поиска RES. Создание очереди
и новых таблиц недеструктивно: старые публикации, компании и статусы сохраняются.
Выдача использует существующие аренду, heartbeat, контроль числа попыток и
защиту от устаревшего результата.

Обработчик заполняет официальную форму, нажимает штатный checkbox reCAPTCHA и
Buscar. Токены не подставляются. Слушатели двух штатных ответов — Busqueda и
DatosActuaciones — устанавливаются **до** отправки. Для получения всех действий
используется список, которым сам сайт заполняет DataTables, а не текущая страница
таблицы. Пустой DOM сразу после загрузки не считается отрицательным результатом.

Сопоставление выполняется по RUT. При поиске названием нужны точное
нормализованное имя и единственный RUT среди совпадений; неоднозначные результаты
помечаются отдельно. Даты берутся из rso_fechacreacion: поле rso_fecha содержит
.NET timestamp и не является отображаемой строкой даты. CVE сохраняет регистр.

В одной транзакции записываются:

- `res_lookup_results`: ответ для компании и список действий, включая найденный RUT.
- `documents`: уникальные CVE со статусом candidate.
- `res_document_sources`: источник RES, дата/тип действия, номер обращения.
- `certificate_download`: задания следующего этапа проверки/скачивания.
- Завершение соответствующего задания res_company_lookup.

Поиск компаний заканчивается постановкой CVE в очередь. Скачивание через
Verificar Certificados реализовано отдельным обработчиком `scripts/res_download.sh`.

## Скачивание PDF

```bash
# VERTIKAL GROUP: один CVE из существующей БД.
bash scripts/res_download.sh --cve ACuKDHhqsvAd --limit 1 \
  --run-id vertikal-pdf-20261111 --profile data/res-search-pilot/profile

# Следующие 10 уникальных CVE: один браузер, две вкладки, общий темп 6/минуту.
bash scripts/res_download.sh --limit 10 --workers 2 --run-id res-pdf-10

# Продолжить после CAPTCHA с ручным участием в видимом браузере.
bash scripts/res_download.sh --limit 10 --run-id res-pdf-10 \
  --headed --captcha-wait 120 --retry-errors

# Статистика и экспорт без браузера.
bash scripts/res_download.sh --action status
bash scripts/res_download.sh --action export
```

Вход — очередь `certificate_download` той же `companies.sqlite3`; `--cve`
ограничивает уже известные коды и может повторяться. `--limit` ограничивает число
разных CVE, а не компаний: у компании может быть несколько документов.
Параметры `--output`, `--profile`, `--workers`, `--timeout`, `--rate-per-minute`,
`--max-attempts` настраиваются независимо от поиска. По умолчанию профиль
`data/res-certificates-profile`; один профиль нельзя одновременно использовать
в двух процессах. В живом тесте использован существующий профиль поиска RES.

Camoufox открывает штатную форму, заполняет CVE, нажимает обычный checkbox
reCAPTCHA и кнопку проверки. При дополнительном задании нужен оператор;
в этом случае очередь останавливается с `captcha_required`. Аккаунт DeQuienes
не нужен. PDF скачивается самим Firefox по ссылке из ответа проверки;
просмотрщик PDF отключён, чтобы браузер выдавал событие download. Слушатели
ответа и скачивания устанавливаются до нажатия кнопки.

Проверяются официальный адрес, совпадение ссылки ответа со скачиванием,
успешное завершение скачивания, сигнатура PDF, маркер конца файла и размер
не более 50 MiB. Проверка формата не заменяет криптографическую проверку
подписи документа. Файлы сохраняются атомарно в
`pdf/<sha256(CVE)>/<sha256(PDF)>.pdf`, рядом — `manifest.json`. Регистр CVE
сохраняется; хеши путей предотвращают коллизии на файловых системах без учёта
регистра. Нативное скачивание завершает передачу до проверки размера на диске.

В одной транзакции записываются `document_files` (CVE, относительный путь,
SHA-256, размер, адрес скачивания, время), статус `documents.downloaded`,
результат `certificate_download_results` и завершение задания. Проверяется
действующая аренда задания. CAPTCHA/ошибки не отмечают документ скачанным.
После прерывания между сохранением файла и транзакцией локальный manifest
проверяется по CVE и SHA-256: исправный файл позволяет завершить задание без
повторного обращения к сайту. Завершённые задания пропускаются, браузер
запускается только при фактической необходимости нового скачивания.

Отчёты: `res_download_report.json/csv`, копия
`res_downloads/<run_id>.json/csv`, общие `document_files.csv` и `cve_queue.csv`.
`--retry-errors` возвращает failed/blocked/captcha_required только этой стадии;
при указанном `--run-id` и/или `--cve` учитывает эти ограничения.

## Ошибки и CAPTCHA

`not_found` устанавливается только по явному пустому ответу реестра. Отдельно
сохраняются completed, no_cve_found (действия есть, CVE нет), ambiguous_match,
retry_wait/failed, blocked и captcha_required. Неизвестный формат ответа или
ошибка парсинга никогда не превращаются в «ничего не найдено».

При необходимости дополнительной CAPTCHA выдача новых заданий останавливается,
остаток очереди сохраняется. Для ручного прохождения на рабочем столе:

```bash
bash scripts/res_search.sh --limit 50 --run-id res-main-20261111 \
  --profile data/res-search-pilot/profile --workers 1 \
  --headed --captcha-wait 120 --retry-errors
```

Это продолжение фактически запущенного пилота. В открытом окне можно решить
дополнительное задание; скрипт ждёт отметки checkbox и продолжает штатную форму.
`--retry-errors` явно возвращает failed/blocked/captcha_required текущего
именованного запуска в работу; завершённые и not_found не затрагиваются.
На сервере без экрана для ручной CAPTCHA нужен удалённый графический доступ.
Бесконечные повторы или смена профилей для обхода CAPTCHA не используются.

## Отчёты и проверки

`res_search_report.json/csv` — текущий запуск; `res_searches/<run_id>.json/csv` —
его сохранённая копия. Сохраняются исходный и найденный RUT, действия, CVE,
ошибки и длительность. Дополнительные общие выгрузки: `res_lookup_queue.csv`,
`res_actions.csv` и `cve_queue.csv`.

Контрольный живой тест: AERO INSPECCIONES SpA → ACiWqbFTpsmy; AGRICOLA NANCAGUA →
явное отсутствие записей. Повторный запуск пропустил отрицательный результат
и после исправления формата даты записал положительный CVE. Артефакты:
`data/res-direct-smoke/`.

Пилот основной базы `res-main-20261111` рассчитан на 50 компаний, но остановлен
CAPTCHA после семи попыток: completed=1, not_found=4, captcha_required=2.
Найден VERTIKAL GROUP SpA, RUT 76615169-8, CVE ACuKDHhqsvAd, CONSTITUCIÓN
от 2016-04-29. Все оставшиеся задания сохранены. Это не завершённый тест 50
компаний и не оценка долгосрочной стабильности реестра.

Обработчик PDF проверен на VERTIKAL GROUP: CVE ACuKDHhqsvAd вернул
11 страниц «CONSTITUCIÓN DE SOCIEDAD POR ACCIONES», RUT 76.615.169-8,
дата 2016-04-29. Файл основной очереди — 953680 байт, SHA-256
`382ef239339f0ed35abb7b24d25867ab38345c290e19e4a99330921fca04d129`.
В БД документ имеет статус downloaded, задание — completed. Повтор того же
`vertikal-pdf-20261111` не открыл браузер, не скачал файл повторно и не увеличил
счётчик попыток. Первое скачивание отдельным исследовательским скриптом лежит
в `data/res-verify-probe/`; основной результат и отчёты — в
`data/dequienes-companies-2025/`.
