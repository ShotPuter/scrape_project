# Непрерывный RES в Docker

Один запуск `bulk-continuous` выполняет поиск по завершённым дням от новых к старым,
начиная со вчерашнего дня в Чили и до 2013-01-01. Даты выбирать не требуется.
После обработки архива проверяются новые завершённые дни. Сначала обрабатывается
сохранённая очередь CVE; готовые PDF пропускаются. Очередь, ссылки и паузы сохраняются.

Один принятый токен используется для последовательной верификации всех доступных
CVE до истечения или отказа. Числа 10/100/200 не ограничивают общий запуск.
Токен автоматически обновляется при истечении; после повторного отказа начинается пауза.
Четыре HTTP-воркера скачивают выданные ссылки одновременно с верификацией:
загрузка байтов не занимает время жизни токена. Whisper base, Chrome и Xvfb находятся в образе.

При транспортной ошибке выбирается следующий настроенный прокси. При CAPTCHA,
HTTP-блокировке и суточном лимите прокси не переключается. После суточного лимита
сохраняется срок ожидания 24 часа, затем сбор продолжается автоматически.
Перезапуск контейнера не сбрасывает срок. При повторном лимите ожидание повторяется.
Активная пауза не создаёт браузеров и запросов к RES.

Прокси берутся из Webshare, затем Bright Data, затем из частного файла
`data/residential-proxies.txt`, если он существует. Не настроенные провайдеры пропускаются.
Поддерживаются и сохранённые бесплатные прокси из этого файла; новый режим сам
не сканирует публичные каталоги. Проверки репутации остаются обязательными.
Старый процесс `free-stream` не останавливается и его очередь не изменяется.

## Установка и запуск

Нужны Docker Engine и Compose v2 на Linux x86-64, около 6 ГБ памяти и 10 ГБ диска для сборки.

```bash
git clone --branch feature/chile-dequienes-res git@github.com:ShotPuter/scrape_project.git
cd scrape_project
cp .env.res.bulk.example .env.res
nano .env.res
mkdir -p data
```

На существующей установке сохраните `.env.res`. Заполните:

```dotenv
WEBSHARE_API_TOKEN=...
ABUSEIPDB_API_KEY=...
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
PROXY_REPUTATION_MODE=blocklist_only
```

`blocklist_only` проверяет обязательные общие списки блокировки без индивидуального
CHECK. Bright Data и файл дополнительных прокси необязательны. Для прямого
подключения задайте `RES_CONTINUOUS_PROVIDERS=direct`.

```bash
dc() { docker compose --env-file .env.res -f compose.res.yml -f compose.res.bulk.yml "$@"; }
dc build res
dc run --rm --user 0 --entrypoint sh res -c \
  'mkdir -p /app/data/res-bulk && chown 1000:1000 /app/data /app/data/res-bulk'
dc up -d res
dc logs -f --tail=100 res
```

Затем дополнительных действий не требуется. Docker восстанавливает контейнер
после перезагрузки хоста (`unless-stopped`). Остановка: `dc stop res`;
продолжение: `dc up -d res`.

Telegram сообщает о запуске, первых PDF, смене прокси при сетевом сбое,
паузе и продолжении, остановке. Каждые 5 минут приходит статистика:
всего/новых PDF и прирост за период, размер, скорость, найденные CVE,
оставшаяся очередь, ошибки, токены, сетевые переключения и время возобновления.
Если Telegram недоступен, сбор продолжается; события сохраняются локально.
Интервал меняется через `RES_TELEGRAM_INTERVAL_MINUTES`.

## Результаты и настройки

По умолчанию результаты находятся в `data/res-bulk/res-continuous/`:

- `tracking.sqlite3` — очередь CVE, серверные ссылки, готовые PDF и SHA-256;
- `progress.json` — состояние и статистика, обновляются каждые 15 секунд;
- `continuous-state.json` — пауза и счётчики, переживающие перезапуск;
- `last-cycle.json` — результат последней верификации;
- `events.jsonl` — журнал уведомлений;
- `ready-downloads/pdf/` — PDF и манифесты.

`RES_BULK_WORKERS=4` задаёт параллелизм загрузки; `RES_BULK_INTERVAL=0.1` — интервал HTTP-запросов.
`RES_CONTINUOUS_RUN_ID` задаёт отдельный каталог. `RES_CONTINUOUS_FROM_DATE` позволяет
ограничить глубину архива, по умолчанию 2013-01-01. Старые `RES_BULK_LIMIT`,
`RES_START_DATE`, `RES_END_DATE` для непрерывного режима не используются.
`RES_BULK_BATCH_SIZE=0` не ограничивает очередь; положительное значение нужно
только для ограниченных диагностических циклов, не задаёт общий лимит процесса.

Для продолжения существующей bulk-базы укажите её каталог через
`RES_CONTINUOUS_RUN_ID`; готовые файлы и завершённые дни сохраняются.
Очередь прежнего `free-stream` в другую базу автоматически не переносится.
Не запускайте два процесса с одной bulk-базой: это блокируется файловой блокировкой.

Проверка конечного цикла на отдельной базе (без запуска постоянного сервиса):

```bash
dc run --rm res bulk-continuous --db data/res-bulk/check/tracking.sqlite3 \
  --run-id check --start 2025-07-29 --end 2025-07-29 \
  --providers webshare --batch-size 10 --max-cycles 1
```

Секреты, SQLite, PDF и профили исключены из Git и build context.
Токены CAPTCHA в отчёты не записываются.

Проверено 18 ноября 2026 в Docker: один токен принят для 10 CVE, сохранены
10 PDF; проверены SHA-256 и `pdfinfo`, а также докачивание после прерывания.
Telegram доставил уведомления без ошибок. При отказе CAPTCHA другой реальный
тест сохранил паузу и очередь без переключения IP. Ожидание суточной квоты
и продолжение после её срока проверены автоматическими тестами без ожидания 24 часов.
