# DeQuienes: реализованные этапы 1–3

В ветке `feature/chile-dequienes-res` реализованы конфигурация, постоянные очереди
и публичный сбор. Браузеры поиска через аккаунт и скачивания RES относятся к
следующим этапам и этим запуском не открываются. Прокси и несколько браузеров
одного обработчика также не включены: неподдерживаемая настройка отклоняется.

## Автоматический гибрид: Camoufox → HTTP

По умолчанию `public.transport = "hybrid"`. Скрипт сам запускает один Camoufox
с одной служебной вкладкой, открывает sitemap и ожидает автоматическую проверку
сайта. При необходимости он также открывает главную и ждёт готовности страницы.
Ручное копирование cookies, вход в аккаунт и нажатия Enter для публичного этапа
не нужны. Cookies и User-Agent автоматически передаются в асинхронный curl_cffi
HTTP-клиент. Браузер остаётся открытым до конца запуска для обновления сессии.

Далее **sitemap и публикации загружаются через HTTP**, без открытия вкладок для
компаний и исполнения JavaScript каждой страницы. Извлечение использует HTML,
возвращённый сервером. `--workers`/`tabs_per_browser` в гибридном режиме означает
количество HTTP-обработчиков; фактическая служебная браузерная вкладка одна.
Лимиты очереди, max_in_flight, rate_per_minute и сохранение результатов прежние.

```bash
bash scripts/dequienes_companies.sh --year 2025 --month 1 \
  --transport hybrid --workers 4 --limit 20 --rate-per-minute 120 --delay 0.3 \
  --output data/dequienes-companies-2025
```

HTTP 403 или страница автоматической проверки вызывает одно общее обновление
сессии: другие обработчики используют его результат. Число обновлений после
первичной подготовки ограничено `public.session_refreshes`/`--session-refreshes`
(по умолчанию 2). Для одного HTTP-запроса разрешена одна повторная попытка после
обновления. При устойчивой блокировке конвейер сохраняет задания и завершает
выдачу новой работы, а не бесконечно запускает браузеры. Если сайт требует
действий человека вместо автоматической проверки, автономный запуск не может
гарантировать доступ; сохранённая очередь остаётся доступной для продолжения.

HTTP 429 не обновляет сессию: учитывается Retry-After и останавливается выдача
новых заданий. HTTP-редиректы не выполняются; запросы и перенос cookies ограничены
публичным доменом dequienes.cl. Размер ответа ограничен 10 MiB даже при отсутствии
Content-Length. Проверка TLS включена. Cookies HTTP-клиента находятся в памяти
и не выводятся в логи/отчёты; браузер использует свой постоянный профиль.

`hybrid_report.json` содержит число явных навигаций browser.goto, обновлений
сессии, HTTP-запросов и успешных HTTP-ответов; cookies/User-Agent туда не пишутся.
Старый режим остаётся доступен через `--transport browser`.

Живой пилот: первый запуск — 5 публикаций, 7 успешных HTTP-запросов (две карты
и пять страниц), одна явная браузерная навигация. Второй запуск в ту же базу —
ещё 3 публикации, 5 успешных HTTP-запросов и одна явная браузерная навигация.
Всего 8 записей completed, каждая с одной попыткой. Артефакты:
`data/dequienes-hybrid-pilot/`. Дополнительно проверен новый профиль:
автоматическая проверка Cloudflare завершилась без ручных действий, затем
одна публикация была загружена через HTTP. Артефакты:
`data/dequienes-hybrid-fresh-pilot/`. Устойчивость обновления сессии и конкурентная
работа проверяются также тестами с моделированием HTTP 403/429.

## Запуск

```bash
# Проверить настройки без базы, браузера и сетевых запросов.
bash scripts/dequienes_companies.sh --config examples/dequienes.toml --show-config

# Пилот: январь 2025, до 20 разных публикаций, две вкладки.
bash scripts/dequienes_companies.sh --config examples/dequienes.toml

# Прежний CLI поддерживается. Для следующей порции — повторить команду.
bash scripts/dequienes_companies.sh --year 2025 --month 1 --limit 20 \
  --workers 2 --rate-per-minute 60 --output data/dequienes-companies-2025

# Состояние очередей и экспорт: без браузера/аккаунта/сети.
bash scripts/dequienes_companies.sh --action status --output data/dequienes-companies-2025
bash scripts/dequienes_companies.sh --action export --output data/dequienes-companies-2025
```

Настройки: [examples/dequienes.toml](../examples/dequienes.toml). CLI имеет
приоритет над файлом. `public.max_items`/`--limit` — лимит разных публикаций за
запуск; `account.max_items`/`--max-companies` и `res.max_items`/`--max-documents` —
независимые лимиты для будущих обработчиков. Они не ограничивают создание
заданий в очереди: их будут применять при выдаче работы соответствующему этапу.
Одна компания может иметь несколько публикаций и CVE.

Пропущенный max_items — без лимита; 0 — ничего не обрабатывать. Чтобы отменить
лимит из файла, уберите max_items из TOML. Отрицательные лимиты запрещены.
`--workers` управляет HTTP-обработчиками гибрида или вкладками режима browser. Предел
`--max-in-flight` применяется к running-заданиям public_discovery в общей базе.
Общий `--rate-per-minute` через ту же базу ограничивает навигации публичного
сборщика, включая загрузки sitemap; это не счётчик всех CSS/JS-запросов браузера.
`--delay` — дополнительная пауза каждой вкладки между заданиями.

## Постоянные очереди

База остаётся в `--output/companies.sqlite3`, используется SQLite WAL.

- `public_discovery`: страницы публикаций для загрузки и извлечения данных.
- `company_lookup`: компании без найденной ссылки/явной пометки CVE RES.
- `certificate_download`: CVE-кандидаты с явным указанием на RES.

Вставка компании, источников, кодов, следующего задания и завершение текущего
делаются одной транзакцией. CVE сравниваются с учётом регистра. Повторяющийся CVE
не создаёт вторую задачу, но все источники сохраняются. Если у компании уже есть
задача company_lookup из другой публикации, нахождение публичного CVE её не
удаляет: это не доказательство полноты истории документов компании.

Задание выдаётся с owner/token/lease_until. Браузерный обработчик продлевает
аренду heartbeat. При падении просроченное задание доступно следующему
обработчику до исчерпания попыток. Результат с устаревшим token не записывается.
При Ctrl+C начатая работа освобождается с retry_wait, а успешные результаты
сохраняются сразу. Время до повторной попытки задаёт retry_seconds. Обработчик
заканчивает запуск, когда сейчас нет доступной работы; ожидание будущих retry
в режиме демона пока не реализовано. Следующий запуск возьмёт готовые повторы.

Для двух процессов на одной машине используйте одну output-базу и **разные
профили**. Чтобы разделить между ними один общий лимит, укажите одинаковый
`--run-id`, например `jan2025-pilot`, и одинаковый `--limit`. Без run-id каждый
запуск получает собственный лимит. Занятые задания учитываются в лимите; повтор
после истечения аренды использует прежнюю резервацию. Продолжение именованного
запуска не увеличивает его лимит. Очередь и лимит уже существующего run-id
менять нельзя — для другого объёма задайте новый ID.

Общую SQLite не размещайте на сетевом диске; несколько серверов требуют другого
backend очередей. Блокировка всей output-директории убрана; профили защищены
от одновременного открытия. CSV-экспорты сериализованы и читают единый снимок базы.

## Миграция прежнего сбора

При первом открытии выполняется недеструктивная миграция прежней companies.sqlite3.
Все строки publications, названия и ссылки сохраняются. Собранные публикации
становятся completed и не загружаются повторно; компании попадают в очередь
поиска. Для них фиксируется `publication_scans.not_scanned`, поскольку раньше
HTML не проверялся на CVE. Новые страницы получают `scanned`.

Для явной повторной проверки старых страниц на коды:

```bash
bash scripts/dequienes_companies.sh --year 2025 --month 1 --limit 20 \
  --rescan-legacy --output data/dequienes-companies-2025
```

Названия при этом не удаляются; scanned-страницы не переоткрываются этой опцией.
Перед первым переходом на новый конвейер остановите старую версию сборщика:
старый процесс не знает о новых очередях. Оригинальные браузерные блокировки
не удаляются автоматически и живые процессы не завершаются принудительно.

При исчерпании попыток — failed. При HTTP 403 — blocked, работа текущего
публичного обработчика приостанавливается; HTTP 429 также прекращает выдачу новых
заданий этим обработчиком. Автоматической смены IP здесь нет. После устранения
причины оператор может явно вернуть failed/blocked в очередь:

```bash
bash scripts/dequienes_companies.sh --year 2025 --month 1 --limit 20 \
  --retry-errors --output data/dequienes-companies-2025
```

Опция сбрасывает ошибочные публичные задания в этой базе, но не трогает running.
Выбор месяца затем ограничивает выдачу заданий.

## Что считается кодом

Публичный сбор извлекает название из h1 и дату публикации, RUT — из заголовка
при наличии. Для юридической идентичности RUT дополнительно проверяется по
контрольному символу; без валидного RUT сохраняется сущность name_candidate.
Одинаковое название не доказывает, что это одно юридическое лицо.

Классификация в `code_candidates`:

- `diario_oficial`: числовой ID публикации из URL; **не отправляется в RES**.
- `ambiguous`: обычная подпись `CVE: ...`; хранится как свидетельство, в RES не отправляется.
- `res_reference`: CVE в HTTPS-ссылке официального RES с параметром cve/codigoverificacion
  либо явно квалифицированной подписью `CVE RES: ...`/`RES CVE: ...`.

Даже res_reference остаётся непроверенным кандидатом: documents.status=candidate.
Скрипт не утверждает, что такой сертификат существует. Произвольные коды,
номера публикаций и содержимое JavaScript не превращаются в CVE RES.

## Артефакты

- `companies.csv`, `publications.csv`, `summary.json` — прежние выгрузки.
- `company_queue.csv` — задания для поиска через аккаунт, включая тип идентичности.
- `cve_queue.csv` — кандидаты RES и статусы проверки/очереди.
- `code_candidates.csv` — все виды найденных кодов и контекст.
- `queues.json` — количества по очередям, компаниям и проверке публикаций.
- В SQLite также хранятся runs/run_jobs, job_attempts, источники компаний/документов.

Для воспроизведения на сохранённом HTML без браузера:

```bash
bash scripts/dequienes_companies.sh --limit 1 --output data/dequienes-offline \
  --import-publication 'https://dequienes.cl/diario-oficial/2025/01/02/company-spa-1234567' saved.html
```

HTML должен соответствовать URL по дате и иметь заголовок публикации. В импортном
режиме выбираются только явно переданные URL, без захвата других заданий базы.
Этот режим удобен для проверки извлечения, но он не подтверждает доступность
страниц или документов в интернете.

## Проверки

Проверены миграция старой базы, транзакционный rollback, два конкурирующих
процесса, общий лимит, heartbeat/истечение аренды, защита от устаревших результатов,
повторная вставка CVE с учётом регистра, классификация кодов, конфигурация и
режимы без браузера. Живой пилот: обработаны 3 публикации ноября
2026, затем повторный запуск добавил ещё 2 без повторной загрузки первых трёх.
Во всех пяти найден только Diario Oficial ID, CVE RES не найден. Результат:
компании в company_lookup, а certificate_download пустая. Проверка выполнялась
с ранее рабочим профилем; доступ свежего профиля через Cloudflare не гарантирован.

## Сохранение аккаунтной сессии для следующего этапа

На рабочем столе запустите `bash scripts/dequienes_login.sh`. Откроется видимый
Camoufox с отдельным постоянным профилем `data/dequienes-account-profile`.
Нажмите Entra con Google, войдите вручную и дождитесь возврата на DeQuienes.
После проверки нажмите Enter в терминале: браузер штатно закроется и сохранит
профиль. Повторный запуск той же команды открывает тот же профиль; при истечении
авторизации потребуется новый вход. Инструмент не проверяет успешность входа
и не выдаёт сохранённый профиль за подтверждённую авторизацию.

Путь можно задать через `--profile`. Профиль аккаунта отделён от публичного
гибридного сборщика. Не открывайте его одновременно двумя процессами. Пароли
вводятся только в браузере, cookies/токены не выводятся и не экспортируются;
каталог data исключён из Git. Эти файлы дают доступ к сессии — не передавайте
папку профиля другим людям.

## Аккаунтный пилот на 10 компаниях

Добавлен ограниченный браузерный пилот:

```bash
bash scripts/dequienes_account_pilot.sh --limit 10 \
  --output data/dequienes-companies-2025 --profile data/dequienes-account-profile
```

Пилот использует сохранённую сессию, один браузер с виртуальным дисплеем и одну
вкладку. Берёт company_lookup через аренду, ищет по RUT при наличии, иначе по
полному названию. Допускает различия регистра и ударений гласных, но сохраняет
различие ñ/n; при нескольких совпадениях автоматически компанию не выбирает.
При известном RUT совпадение проверяется независимо от названия, которое могло
измениться. Открывает Legal и читает страницы истории до конца с проверкой числа
событий. RES CVE записываются в documents и certificate_download, источники — в
account_document_sources. Все результаты — в company_lookup_results и отчёте.

`account_pilot.csv` и `account_pilot.json` — последний запуск; копии каждого запуска
сохраняются в `account_pilots/<run_id>.csv/json`. Для продолжения того же лимита
используйте `--run-id` из отчёта и прежний `--limit`. Обычный следующий запуск
возьмёт следующую порцию pending, отрицательные результаты не проверяет повторно.
При потере сессии — needs_login; при неоднозначности — ambiguous_match;
распознанная история без RES — no_cve_found. Ошибка/потеря входа останавливает
пилот, вместо того чтобы пометить остальные компании отсутствующими.

Живая проверка 2026-11-09: 10 компаний, 30 юридических событий, все события из
Diario Oficial; CVE RES не найдены. В базе 10 no_cve_found, остальные 105 заданий
company_lookup остались pending. Это результат конкретной выборки из публичных
публикаций, а не утверждение об отсутствии документов RES во всём DeQuienes.
Сохранённый аккаунт позволил выполнить поиск и чтение Legal без ручного входа.
