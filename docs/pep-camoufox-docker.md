# Тест PEP через Camoufox на сервере

Требуется Docker с Compose v2. Исходный Excel уже лежит в
`docs/DECLARACIONES_PEP.xlsx`; контейнер открывает его только для чтения.
Браузер и его модель скачиваются при сборке образа, поэтому первая сборка
потребует несколько гигабайт диска и доступа к PyPI/GitHub.

## Запуск

Из корня распакованного проекта:

```bash
cp .env.camoufox.example .env.camoufox
```

В `.env.camoufox` укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
Без них отчёты остаются в логах и `progress.jsonl`.
Для четырёх браузеров также заполните `BRIGHTDATA_PROXY_USERNAME` и
`BRIGHTDATA_PROXY_PASSWORD` данными зоны Bright Data. Пароль хранится только
в игнорируемом `.env.camoufox`, не в Dockerfile и не в Git.

```dotenv
PEP_WORKERS=4
PEP_LIMIT=100
BRIGHTDATA_PROXY_SERVER=http://brd.superproxy.io:44445
BRIGHTDATA_PROXY_USERNAME=ваш_базовый_логин_зоны
BRIGHTDATA_PROXY_PASSWORD=ваш_пароль
```

```bash
docker compose --env-file .env.camoufox -f compose.camoufox.yml build
docker compose --env-file .env.camoufox -f compose.camoufox.yml up -d
docker compose --env-file .env.camoufox -f compose.camoufox.yml logs -f
```

По умолчанию берутся первые **100 уникальных ссылок** из второй вкладки Excel,
колонка `ENLACE_CONSULTA_LEY_2013`. Дубликаты не обрабатываются повторно.
HTTP-ссылки из Excel преобразуются в HTTPS. Файл Excel не скачивается и не меняется.

Параметры `.env.camoufox`:

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PEP_INPUT` | `./docs/DECLARACIONES_PEP.xlsx` | Путь к Excel на сервере |
| `PEP_LIMIT` | `100` | Число уникальных ссылок, `0` — все |
| `PEP_OFFSET` | `0` | Сколько уникальных ссылок пропустить |
| `PEP_TIMEOUT` | `60` | Таймаут одного действия в секундах |
| `PEP_MAX_MINUTES` | `120` | Общий лимит времени |
| `PEP_WORKERS` | `4` | Независимых браузеров, от 1 до 4 |
| `PEP_MEMORY_LIMIT` | `8g` | Лимит RAM контейнера |
| `PEP_CPUS` | `4` | Лимит CPU контейнера |
| `PEP_SHM_SIZE` | `2gb` | Размер shared memory |
| `PEP_LOG_INTERVAL` | `30` | Интервал heartbeat-логов, от 5 до 300 секунд |

Например, следующая сотня: `PEP_LIMIT=100`, `PEP_OFFSET=100`.
Ссылки распределяются по кругу без дубликатов: 100 ссылок дают 25/25/25/25
для четырёх браузеров или 34/33/33 для трёх. У каждого браузера отдельный
профиль, каталог результатов и свой `-session-...` в логине прокси.
Сессия не меняется при отказах; автоматической ротации нет. При явном отказе
reCAPTCHA останавливается затронутый браузер, остальные завершают свои наборы.
Его оставшиеся ссылки не передаются другим браузерам. При ошибке навигации
фиксируется ошибка и проверяется следующая ссылка этого браузера.

Инициализация Camoufox идёт по очереди, чтобы избежать наблюдавшегося сбоя
нативной библиотеки при одновременной инициализации fingerprint. После
открытия браузеры работают параллельно; пауза 3 секунды действует отдельно
в каждом браузере. Для запуска без прокси задайте `PEP_WORKERS=1` и оставьте
оба proxy credentials пустыми. При неполных настройках прокси программа
возвращает ошибку, а не переходит незаметно на прямое соединение.

Проверка TLS включена. Официальный CA Bright Data для порта 44445 включён
в образ и импортируется только в созданные прокси-профили, после проверки
закреплённого SHA-256. Источник сертификата:
https://docs.brightdata.com/general/account/ssl-certificate.
Перед скачиваниями каждый браузер проверяет свой выходной IP через HTTPS
к api.ipify.org. Разные session ID не гарантируют разные IP: в живой пробе
четыре сессии открыли PEP с HTTP 200, но дали два разных IP. Фактическое
число IP выводится в общей статистике; программа не выдаёт его за четыре.

## Статистика и результаты

Telegram приходит **каждые 10 обработанных уникальных ссылок**, включая ошибки,
и при завершении/остановке (также если последняя группа меньше десяти).
Счётчики накопительные с начала запуска:

- ссылки: полностью скачаны / частично / ошибки / ожидают;
- декларации: скачано / не скачано из найденных;
- число сохранённых PDF и причина остановки.
- время с начала запуска, темп деклараций/мин и число наблюдавшихся proxy IP.

Одна ссылка может содержать несколько деклараций. Если страницу открыть не
удалось, число документов на ней неизвестно: ссылка учитывается как ошибка,
а неизвестные документы не прибавляются к счётчику найденных.
Статистика дублируется в логах и `progress.jsonl`; ошибка Telegram не прерывает сбор.
Токены CAPTCHA, cookies и Telegram credentials в отчёты не записываются.

### Постоянные логи и скорость

В корне каждого `run-<UTC>/` сохраняется **`run.log`** — JSON Lines с UTC-временем.
У каждого `worker-N/` также есть свой **`run.log`**. Все события одновременно
выводятся в stdout и доступны через `docker compose ... logs -f`.
Файлы остаются в volume после остановки или пересоздания контейнера.
Каждый файл ограничен 10 МиБ, сохраняются три предыдущих файла (`run.log.1`–`.3`).
Docker отдельно ротирует stdout/stderr: 10 МБ × 3 файла на контейнер.

Каждые `PEP_LOG_INTERVAL` секунд событие `heartbeat` и обновлённый `report.json`
показывают:

- `elapsed_seconds` — прошедшее время;
- `processed`, `total`, `completed`, `partial`, `failed`, `running`, `pending` — ссылки;
- `downloaded`, `not_downloaded`, `pdf` — декларации и сохранённые PDF;
- `links_per_minute`, `declarations_per_minute` — среднюю скорость с начала;
- `interval_seconds`, `interval_processed`, `interval_downloaded`,
  `interval_declarations_per_minute` — прирост и скорость за последний интервал;
- `workers` — этап каждого браузера, номер текущей ссылки/декларации,
  длительность этапа, счётчики и скорость.

Heartbeat работает и когда ни одна ссылка ещё не завершена. Этапы включают
проверку сертификатов, запуск браузера, проверку прокси, открытие страницы,
поиск деклараций, скачивание и проверку файла. События `link_finished` и
`document_finished` содержат отдельную длительность, статус, HTTP-код и ошибку,
если она наблюдалась. `worker_finished`/`run_finished` фиксируют завершение.
Медленная отправка Telegram не удерживает блокировку heartbeat.

Просмотр живых логов:

```bash
docker compose --env-file .env.camoufox -f compose.camoufox.yml logs -f pep-camoufox
```

Для хранения снаружи Docker скопируйте `/app/data` командой из следующего
раздела. В `progress.jsonl` также сохраняются время и средняя скорость на
границах Telegram-отчётов. В логах скрываются proxy credentials, Telegram
токен, поля cookies/authorization и credentials в URL. Тела POST не логируются.

Результаты хранятся в Docker volume `pep-camoufox-data`, внутри
`/app/data/run-<UTC>/`: общие `report.json`, `sample.json`, `progress.jsonl`.
В `worker-1/` … `worker-4/` лежат индивидуальные отчёты, профили,
`pdf/`, `archives/`, `manifests/`. Пути файлов в общем отчёте включают
каталог браузера. ZIP и PDF проверяются перед отметкой успеха.
Каждый новый запуск создаёт отдельный каталог; это тест, автоматического
возобновления всей очереди после перезапуска здесь нет.

Скопировать результаты на сервер:

```bash
mkdir -p pep-results
docker compose --env-file .env.camoufox -f compose.camoufox.yml cp pep-camoufox:/app/data/. ./pep-results/
```

Остановить с сохранением отчёта:

```bash
docker compose --env-file .env.camoufox -f compose.camoufox.yml stop
```

Для проверки чтения Excel без браузера и без отправки Telegram:

```bash
docker compose --env-file .env.camoufox -f compose.camoufox.yml run --rm pep-camoufox /input/DECLARACIONES_PEP.xlsx --limit 10 --preview
```

При неполном результате программа возвращает exit code 1; подробная причина
находится в `report.json`. Автоматический рестарт отключён.

## Проверки пакета

Compose прошёл `config --quiet`, чтение исходного Excel проверено через
`--preview`. После добавления параллельных браузеров и логов прошли 19 офлайн-тестов:
выбор ссылок, разбиение 100/4 и 100/3 без дубликатов, конкурентная обработка,
границы общих Telegram-отчётов, отсутствие прямого fallback, скрытие credentials,
последовательная нативная инициализация при четырёх работающих браузерах,
отчёт о совпадающих IP, heartbeat во время незавершённого скачивания,
расчёт средней/интервальной скорости, ротация и скрытие секретов в файлах
и stdout. Ruff без замечаний. Живая проверка четырёх браузеров
через предоставленную прокси-зону дала HTTP 200 для PEP во всех четырёх;
зафиксированы два разных IP. Полная сотня в новом параллельном режиме ещё
не проверена. Изменение количества браузеров само по себе не гарантирует
пропорционального ускорения или принятия CAPTCHA.
Полную локальную сборку и запуск контейнера подтвердить не удалось:
загрузки зависимостей с PyPI обрывались/зависали, в том числе через сеть хоста.
Архив содержит исходники для сборки на сервере, а не готовый Docker image.
