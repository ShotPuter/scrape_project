# RES: непрерывная очередь бесплатных прокси

Режим `free-stream` собирает кандидатов через HTTP из зарегистрированных источников,
проверяет репутацию до подключения, затем проверяет выходной IP и доступность страниц
RES. Каждый готовый прокси сразу поступает свободному слоту: ждать подготовки всех
пяти не требуется. Одновременно работают не более пяти браузеров этого диспетчера,
по одной CAPTCHA-вкладке. Проверка HTTP сама браузеров не создаёт.

Слот сохраняет один браузер и HTTP-сессию, получает компании по одной из общей
SQLite-очереди и сохраняет результат каждой компании сразу. Ограничений на 10/50
компаний или число CAPTCHA-токенов в этом режиме нет. Сессия работает до отказа
маршрута, CAPTCHA, смены IP, явного лимита, общей паузы или исчерпания очереди.
После остановки слот берёт следующий проверенный прокси. Совпадающий выходной IP одновременно двум слотам не выдаётся.
Доступность HTTP ещё не гарантирует прохождения CAPTCHA.

## Суточный лимит

Явный ответ RES «No es posible generar más de 100 documentos diarios» отправляет
только текущий прокси и его наблюдаемый выходной IP на паузу, по умолчанию 24 часа.
Браузер закрывается; незавершённые компании возвращаются в очередь без расходования
попытки из-за этого лимита. Другие проверенные маршруты продолжают работу. Пауза
сохраняется в SQLite после перезапуска; альтернативный endpoint с тем же выходным
IP тоже не допускается до её окончания.

Область действия квоты RES не подтверждена: смена IP не гарантирует снятия ограничения.
Режим реализует раздельную обработку маршрутов, но не обещает неограниченного числа
документов. Обычный `benchmark` сохраняет прежнюю общую остановку по суточному лимиту.

## Настройка и запуск

Используйте существующий `.env.res` с ключом AbuseIPDB для пакетного blacklist и
настройками Telegram. Не публикуйте секреты. Добавьте или измените:

```dotenv
RES_RUN_ID=res-free-2025-01-1000
RES_YEAR=2025
RES_MONTH=1
RES_LIMIT=1000
RES_BROWSERS=5
RES_COMPANY_ATTEMPTS=3
PROXY_REPUTATION_MODE=blocklist_only
RES_CAPTCHA_TIMEOUT=130
RES_FREE_TELEGRAM_INTERVAL_MINUTES=30
RES_FREE_SOURCES=all
RES_FREE_MAX_CANDIDATES=0
RES_FREE_SOURCE_RECORDS=0
RES_FREE_PROXY_PORTS=80,443
RES_FREE_BATCH_SIZE=10
RES_FREE_SITE_LIMIT_HOURS=24
RES_FREE_IDLE_MINUTES=0
RES_FREE_MAX_COOLDOWNS=0
RES_ERROR_COOLDOWN_MINUTES=10
RES_MAX_FAILURES=20
```

`RES_FREE_IDLE_MINUTES=0` означает ожидание новых пригодных прокси без таймера
завершения. `RES_FREE_MAX_COOLDOWNS=0` разрешает повторять общие паузы по сериям
ошибок без ограничения числа циклов. После успешного завершения выбранных компаний
процесс заканчивается; компании с исчерпанными обычными попытками остаются ошибочными.
Для их повторной обработки задайте `RES_RETRY_ERRORS=1`. Для другой выборки используйте
новый `RES_RUN_ID`; готовые документы из общей tracking-БД переиспользуются.

```bash
docker compose --env-file .env.res -f compose.res.yml -f compose.res.free.yml build res
docker compose --env-file .env.res -f compose.res.yml -f compose.res.free.yml up -d --force-recreate res
docker compose --env-file .env.res -f compose.res.yml -f compose.res.free.yml logs -f --tail=100 res
```

Overlay явно включает сбор публичных прокси только для этого режима. Общий сборщик
прокси включать отдельным контейнером не требуется. Обязательные FireHOL, NoCoin,
Spamhaus DROP, пакетный AbuseIPDB и статические запреты продолжают действовать;
`blocklist_only` не делает индивидуальных CHECK-запросов. Отсутствие пригодного
актуального обязательного списка запрещает использование непроверенных маршрутов.

Записи источников и размер очереди по умолчанию не обрезаются: оба параметра
`RES_FREE_SOURCE_RECORDS` и `RES_FREE_MAX_CANDIDATES` равны 0. Сохраняются ограничения
16 МиБ на HTTP-файл источника и 128 МиБ на сырой дисковый кэш. Отбор проходит этапами:
удаление дубликатов → числовой публичный IPv4 и поддерживаемый протокол → восемь
запрещённых сетей → пакетные блоклисты → разрешённые порты → очередь HTTP-проверок.
Снимки блоклистов читаются один раз на пакет, индивидуальные API-запросы на этом
этапе не выполняются. Актуальная проверка перед подключением дополнительно сохраняется.
Обновление каталога удаляет из очереди неактивные адреса, не попавшие в новый отбор;
активные аренды, PDF, компании и отдельная таблица суточных пауз IP сохраняются.

В статистике отдельно показаны потери на каждом этапе, причины по фидам и часто
исключаемые порты. Допуск HTTP по-прежнему не гарантирует работоспособности CAPTCHA.
Восемь запрещённых диапазонов не являются полным перечнем всех сетей Alibaba.

По умолчанию принимаются числовые публичные IPv4-прокси на портах 80/443.
`RES_FREE_PROXY_PORTS` позволяет явно расширить прикладной список, например до
`80,443,8080,3128,8000,8888,1080,1081`. Это не меняет сетевые правила хоста: если
установлен DOCKER-USER фильтр, для нестандартных портов нужны отдельные разрешения
на конкретные проверенные endpoint согласно инструкции фаервола. Для
проверенного нестандартного endpoint задайте `RES_FREE_ALLOWED_PROXY_ENDPOINTS`
списком точных `IP:port` через пробел и отдельно согласуйте его с установленным
[фаерволом хоста](docker-egress-firewall.md). Скрипт не меняет iptables автоматически.
Существующие запрещённые сети через исключения разрешить нельзя.

## Состояние и продолжение

В смонтированной `data/res-benchmark/` сохраняются:

- `free-runtime.sqlite3`: очередь компаний, аренды прокси, паузы маршрутов/IP;
- `tracking.sqlite3`: общая история компаний, CVE, попыток и путей к PDF;
- `<RES_RUN_ID>/progress.json` и `summary.json`: прогресс, активные слоты, паузы;
- `<RES_RUN_ID>/workers/wNN/`: PDF, промежуточные результаты и логи.

Повторный запуск с той же выборкой продолжает очередь. Валидные готовые PDF
проверяются и переиспользуются; их повторная загрузка не требуется. Не удаляйте БД
или каталоги PDF для продолжения. Общая блокировка каталога не допускает запуска
второго такого диспетчера поверх первого; она не ограничивает посторонние контейнеры.

Telegram получает подготовку и запуск, результат загрузки источников, первый
допущенный прокси с его выходным IP, первый запуск процесса и подтверждение IP
браузера, а также первые сохранённые PDF. Запуск процесса и готовность браузера
показываются раздельно: готовность означает совпадение HTTP- и браузерного IP.
Повторные ротации, завершения сессий и лимиты прокси объединяются раз в 5 минут.
Общая пауза, возобновление и проблемы обязательных списков отмечаются отдельно.
Если новых PDF нет 10 минут, приходит предупреждение; оно не повторяется на каждом
цикле ожидания.

Полная сводка каждые `RES_FREE_TELEGRAM_INTERVAL_MINUTES=30` минут содержит компании
и очередь, PDF за запуск и за период, среднюю скорость и скорость за период,
проверки/допуски прокси, отказы репутации отдельно от ошибок связи, активные
браузеры, попытки компаний и ошибки CAPTCHA, лимиты и длительность. Проверки
прокси считаются с повторными попытками; допуск ещё не гарантирует CAPTCHA.
Старый `RES_TELEGRAM_INTERVAL_MINUTES` управляет другими режимами и не меняет
интервал этого overlay.

Используются прежние `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Отправка идёт через
отдельную ограниченную очередь и не блокирует подбор прокси/браузеры при сбое
Telegram. Итог имеет приоритет перед устаревшими сообщениями после сетевого сбоя.
Счётчики доставки доступны в `progress.json`/`summary.json` в поле `telegram`.
Все события остаются в `<RES_RUN_ID>/events.jsonl` и stdout; журнал ротируется при
5 МиБ с сохранением одного предыдущего файла. Секреты и пароли прокси скрываются.
Образ работает без физического монитора.

Для остановки с сохранением результатов:

```bash
docker compose --env-file .env.res -f compose.res.yml -f compose.res.free.yml stop -t 60 res
```

Из старого запуска может сохраниться общая блокировка `daily_document_limit`.
Её снятие выполняется явным CLI-флагом `--resume-after-site-limit`; новый режим
такую общую блокировку при лимите отдельного маршрута не устанавливает.

## Ошибки SOCKS и сетевой диагностики

Образ устанавливает `httpx[socks]`, а при сборке проверяется импорт `socksio`.
Диспетчер также проверяет зависимость до запуска проверок прокси: отсутствие
SOCKS-поддержки завершает запуск с понятным сообщением вместо массового отбрасывания
кандидатов. После изменения зависимостей образ нужно пересобрать и пересоздать контейнер.

В статистике `configuration_failed` отделён от `connection_failed`.
`failure_reasons` содержит категории `missing_socks_dependency`, `timeout`,
`connect_error`, `tls_error`, `proxy_error`, `protocol_error`, HTTP-коды и ошибки
проверки страниц RES. Категория добавляется и в SQLite-поле `error`, поэтому даже
исключение без текста остаётся видимым при группировке ошибок. `probe interrupted`
означает отмену проверки при остановке и не учитывается как сетевой отказ.

## Повторная проверка ранее рабочих прокси

Если рабочий процесс не получил даже HTTP-IP из-за ConnectTimeout/ConnectError/ReadTimeout
до начала обработки компаний, маршрут помещается в отдельную SQLite-очередь
`free_connection_retries`. Через `RES_FREE_CONNECTION_RETRY_DELAY=30` секунд он
приоритетно проходит полную проверку репутации, выходного IP и обеих страниц RES.
Успех возвращает прокси в готовый пул. Максимум `RES_FREE_CONNECTION_RETRIES=2`
попытки на эпизод восстановления; 1 оставляет одну попытку, 0 отключает эту очередь.
Бюджет не сбрасывается одним лишь успехом HTTP-проверки: повторный отказ рабочего
процесса на том же маршруте не создаёт бесконечного цикла.

Повторные проверки используют существующие HTTP-проверяющие задачи и общий rate limit.
Браузерный слот освобождается перед ожиданием. Компании без начатой попытки возвращаются
в очередь без расходования попыток. Состояние восстановления сохраняется при
перезапуске и обновлении каталога. Ошибки репутации, TLS, CAPTCHA и суточные лимиты
не являются основанием для этого восстановления. В Telegram видны постановка на
повтор, восстановление, счётчики проверок и размер ожидающей очереди.

## Распределение проверок по подсетям

HTTP-проверяющие задачи берут не более двух одновременных проверок одной IPv4 /24,
суммарно для всех протоколов и портов. После пяти последовательных таймаутов
подсеть исключается из новых проверок на 600 секунд. Успешное завершение проверки
сбрасывает серию таймаутов, но не отменяет уже начавшуюся паузу. Прерванная проверка
не считается таймаутом. Репутационные проверки и суточные паузы IP остаются обязательными.

Приоритет: очередь восстановления ранее проверенных маршрутов → ранее успешные
маршруты → новые адреса. Для всех очередей действуют ограничения /24. Время последнего
успеха сохраняется даже после неудачной проверки. Таблица `free_subnets` сохраняет
паузы при перезапуске; Telegram и progress.json показывают число подсетей на паузе.

Адреса больше не удаляются при обновлении или устаревании каталога: `catalog_active=0`
помечает архивные записи. Исторически успешные маршруты доступны для повторной проверки
даже после исчезновения из списка; перед подключением к ним действуют текущие настройки
портов и все репутационные фильтры. Миграция существующей SQLite добавляет поля subnet,
last_success и catalog_active без удаления компаний, CVE и PDF.

## Непрерывная браузерная сессия

`RES_FREE_SESSION_NETWORK_RETRIES=2` разрешает два повтора временных сетевых ошибок
в том же браузере и HTTP-сессии; 0 отключает повторы. Перед повтором выдерживается
пауза 3 секунды. При ошибках CAPTCHA, репутации, TLS, смене IP или явном суточном
лимите браузер закрывается без таких повторов. После исчерпания повторов в stop_reason
сохраняется исходная ошибка, а не общий текст Queue paused.

Каждый новый запрос поиска/проверки получает новый CAPTCHA-токен: одноразовый POST
не воспроизводится. Найденные CVE/codigo и уже сохранённые PDF восстанавливаются из
tracking-БД при выдаче компании; повторный проход скачивает только недостающие файлы.
Завершённая компания подтверждается в общей очереди сразу. При аварии родитель
освобождает оставшуюся аренду только своего worker owner.

Параметры RES_FREE_BATCH_SIZE и RES_TOKENS_PER_PROXY остаются для совместимости, но
больше не ограничивают free-stream. RES_FREE_WORKER_TIMEOUT теперь ограничивает
отсутствие прогресса, а не общую продолжительность здоровой сессии. Проверки выходного
IP и его репутации выполняются на границе каждой компании. Лимит браузеров остаётся 5.
